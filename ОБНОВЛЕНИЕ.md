# Как править параметр и как выкатывать

---

## Коротко

1. Правите значение в `app/src/data/` — один файл, всё в одном месте.
2. `npx vitest run` — если эталоны разошлись, тесты падают и говорят где.
3. `git commit && git push` в `main` — дальше само.

Публикация занимает 2–3 минуты. Если тесты не прошли, **сайт не обновится** —
это защита от выкатки расчёта, который разошёлся с книгой.

---

## Где что лежит

| Что править | Файл |
|---|---|
| Курсы, пошлины, контрактные цены, логистика, котировка CZCE | `app/src/data/calc.ts`, объект `INPUT` |
| Заход сырья, выходы, ставки отгрузки по моделям | `app/src/data/models.ts` |
| Контрольные значения эталонов | `app/src/data/references.ts` |
| Формулы расчёта | `app/src/domain/` — трогать только при пересмотре модели |

## Пример: пришли новые ставки МСХ на месяц

В `app/src/data/calc.ts`:

```ts
duties: {
  sunOil:  { value: <новая ставка>, month: '<YYYY-MM>', note: 'введено <дата>' },
  sunMeal: { value: <новая ставка>, month: '<YYYY-MM>', note: 'введено <дата>' },
  ...
}
```

Плюс `CURRENT_MONTH` в том же файле, если начался новый месяц.

**Месяц обязателен.** Если он не совпадёт с текущим, М2 и М5 встанут
с сообщением, какой именно ставки не хватает. Это не сбой, а защита:
прошлым месяцем не считаем и старым значением не подменяем.

## Пример: изменился выход продукции

В `app/src/data/models.ts` у нужной модели правится **только заданный**
выход — `kernel`, `cat3`, `husk` или `oil`. Полуфабрикат и жмых **производные**
и пересчитаются сами:

```
F2 = 1 − F1 − F3 − F4        F6 = (1 − потери) − F5
```

Если сумма выходов выйдет за 100 %, расчёт остановится и скажет об этом —
вместо того чтобы показать отрицательные тонны и правдоподобную
рентабельность.

## Пример: изменилась контрактная цена

`app/src/data/calc.ts`, объект `INPUT.contracts`. Цены **в валюте контракта**,
конвертация и вычеты считаются сами по единой формуле:

```
нетто = контракт × курс − пошлина(₽/т или % от контракта) − логистика(₽/т)
```

## Что произойдёт с эталонами

Эталоны A, B и C — это снимки **на фиксированных входах**. Меняя рабочие
параметры, вы не должны их ломать: тесты подставляют собственные значения.

Если тест эталона всё же упал — значит правка задела **формулу**, а не вход.
Это стоп-сигнал: разбираться, а не подгонять допуск.

Отдельный сторож `wiring.test.ts` сверяет то, что показано на экране,
с эталоном (C). Он ловит подмену входа — например, если вместо канонической
цены контракта по М4 подставить округлённую котировку.

## Проверка перед пушем

```bash
cd app
npx vitest run        # эталоны A, B, C, граф блокировок, сторожа
npx tsc -b --noEmit   # типы
npm run lint          # линт
npm run build         # сборка
npm run preview       # посмотреть глазами на localhost:4173
```

Те же четыре шага выполняются в GitHub Actions при каждом пуше в `main`.

## Два репозитория — что где

| Репозиторий | Роль |
|---|---|
| **`bdr-pult-web`** (публичный) | код и сайт. Пуш в `main` собирает и публикует Pages |
| `bdr-pult` (приватный) | рабочая история разработки по этапам. Сайт из него не собирается |

Правки приложения делаются в **публичном** репозитории — там живёт CI
и публикация. Приватный остаётся архивом истории; синхронизировать его
с публичным не требуется.

**Локальная ветка `архив-этапы-1-5` не пушится никогда** — в её первом
коммите снимок книги БДР и заметки по ВПС.

## Выкатка

**Проверки — автоматически.** Пуш в `main` → `.github/workflows/checks.yml` →
типы, линт, тесты, сборка. Красный прогон означает, что расчёт разошёлся
с книгой: разбираться, а не игнорировать.

**Публикация — автоматически.** Пуш в `main` → `.github/workflows/pages.yml` →
проверки → сборка → GitHub Pages. Если тесты не прошли, **сайт не обновится**.

Ручной запуск — вкладка Actions, кнопка **Run workflow**.

Локальный просмотр собранного сайта: `cd app && npm run build && npm run preview`.

Откат: `git revert <коммит>` и пуш. **Без rebase, amend и force** — история
только вперёд.

## Сверка с книгой при пересмотре модели

Если менялась не цифра, а **формула**, сверку надо повторить целиком:

1. Обновить снимок книги (**только чтение**, права 444).
2. Прогнать независимый пересчёт и сверку по семи сценариям —
   методика в [СВЕРКА-ЭТАП5.md](СВЕРКА-ЭТАП5.md).
3. При любом расхождении — остановиться и разобраться. **Допуск не трогать:**
   0,011 тыс.₽ унаследован от округления эталонов в ТЗ и при переходе
   на живые данные подлежит ужесточению, а не ослаблению.

Снимок книги и вспомогательные скрипты сверки в репозиторий не входят —
это исходные данные, они закрыты `.gitignore`.
