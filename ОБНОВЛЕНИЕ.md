# Как править параметр и как выкатывать

---

## Коротко

**Текущие цифры правятся прямо в пульте, без кода и без выкатки.** Открыли
сайт, ввели ставку — пять моделей пересчитались немедленно. Введённое хранится
в вашем браузере и никуда не отправляется.

Код и выкатка нужны только тогда, когда меняется **база** — значения,
с которых пульт стартует у всех, — или сами формулы.

---

## Два уровня параметров

| Уровень | Где правится | Что там |
|---|---|---|
| **Общие** | экран «Ставки и курсы» | курсы, пошлины МСХ и месяц их действия, контрактные цены, логистика, настройки расчёта, ФОТ. Действуют на все пять режимов сразу |
| **По модели** | карточка режима, блок «Параметры режима» | заход сырья, цена закупа, выходы, потери, переработка, ставка отгрузки П/Ф. Действуют только на этот режим |

Общий параметр **нельзя** править из карточки режима — там он показан справкой.
Это защита: иначе кажется, что правишь одну модель, а меняются все пять.

Изменённые относительно базы поля помечаются словом «изменено» и получают
кнопку «↺» — вернуть базовое значение. Кнопка «Вернуть базовые значения»
сбрасывает всё сразу и даёт ровно рабочий эталон.

**ФОТ сбрасывается отдельно.** Общий сброс его не трогает: у него своя кнопка
«Очистить ФОТ». Значений ФОТ в репозитории нет — он публичный.

---

## Что делать при обычном обновлении

| Событие | Что сделать |
|---|---|
| Вышли ставки МСХ на новый месяц | «Ставки и курсы» → выбрать месяц, ввести две ставки. Всё |
| Изменилась логистика | там же, таблица «Контрактные цены и логистика» |
| Перезаключён контракт | там же, колонка «контракт» |
| Изменился выход или заход по режиму | карточка режима → «Параметры режима» |

Ничего коммитить не надо. Пересчёт мгновенный, значения сохраняются в браузере.

---

## Когда всё-таки нужен код

| Что править | Файл |
|---|---|
| **База** — значения, с которых стартует пульт | `app/src/state/inputs.ts`, объект `BASE` |
| Сборка «входные данные → ядро → экран» | `app/src/state/compute.ts` |
| Контрольные значения эталонов | `app/src/data/references.ts` |
| Формулы расчёта | `app/src/domain/` — только при пересмотре модели |

**BASE и эталон (C) связаны.** Меняя базу, вы обязаны пересмотреть эталон,
иначе упадёт сторож `wiring.test.ts`. Это не помеха, а страховка: он ловит
подмену входа, а не только ошибку в формуле.

---

## Как ведёт себя месяц ставок

Месяц обязателен. Если он не совпадает с текущим, **М2 и М5 встают**
с сообщением, какой именно ставки не хватает, а М3 продолжает считать —
у неё в цене ставка МСХ не участвует. Это не сбой, а защита: прошлым
месяцем не считаем и старым значением не подменяем.

## Как ведут себя выходы

Правятся только **заданные** выходы: ядро, 3 категория, лузга, масло.
Полуфабрикат и жмых — **производные**, они пересчитываются сами:

```
F2 = 1 − F1 − F3 − F4        F6 = (1 − потери) − F5
```

Обе величины показаны в блоке «Параметры режима» вместе с формулой
и балансом первого передела. Если сумма выходов выйдет за 100 %, расчёт
остановится и скажет об этом — вместо того чтобы показать отрицательные
тонны и правдоподобную рентабельность.

## Как считается цена

```
нетто = контракт × курс − пошлина (₽/т или % от контракта) − логистика (₽/т)
```

Нетто пересчитывается сразу и видно в той же таблице.

## Что произойдёт с эталонами

Эталоны A, B и C — это снимки **на фиксированных входах**. Меняя рабочие
параметры, вы не должны их ломать: тесты подставляют собственные значения.

Если тест эталона всё же упал — значит правка задела **формулу**, а не вход.
Это стоп-сигнал: разбираться, а не подгонять допуск.

Отдельный сторож `wiring.test.ts` сверяет то, что показано на экране,
с эталоном (C). Он ловит подмену входа — например, если вместо канонической
цены контракта по М4 подставить округлённую котировку.

## Проверка перед пушем

```bash
cd app
npx vitest run        # эталоны A, B, C, граф блокировок, сторожа
npx tsc -b --noEmit   # типы
npm run lint          # линт
npm run build         # сборка
npm run preview       # посмотреть глазами на localhost:4173
```

Те же четыре шага выполняются в GitHub Actions при каждом пуше в `main`.

## Где работать

Правки приложения делаются в **публичном** репозитории `bdr-pult-web` —
там живёт CI и публикация. Состав репозиториев и что куда не пушится —
в [ОГРАНИЧЕНИЯ.md](ОГРАНИЧЕНИЯ.md) §9, повторять здесь не буду.

---

## Выкатка

**Проверки — автоматически.** Пуш в `main` → `.github/workflows/checks.yml` →
типы, линт, тесты, сборка. Красный прогон означает, что расчёт разошёлся
с книгой: разбираться, а не игнорировать.

**Публикация — автоматически.** Пуш в `main` → `.github/workflows/pages.yml` →
проверки → сборка → GitHub Pages. Если тесты не прошли, **сайт не обновится**.

Ручной запуск — вкладка Actions, кнопка **Run workflow**.

Локальный просмотр собранного сайта: `cd app && npm run build && npm run preview`.

Откат: `git revert <коммит>` и пуш. **Без rebase, amend и force** — история
только вперёд.

## Сверка с книгой при пересмотре модели

Если менялась не цифра, а **формула**, сверку надо повторить целиком:

1. Обновить снимок книги (**только чтение**, права 444).
2. Прогнать независимый пересчёт и сверку по семи сценариям —
   методика в [СВЕРКА-ЭТАП5.md](СВЕРКА-ЭТАП5.md).
3. При любом расхождении — остановиться и разобраться. **Допуск не трогать:**
   0,011 тыс.₽ унаследован от округления эталонов в ТЗ и при переходе
   на живые данные подлежит ужесточению, а не ослаблению.

Снимок книги и вспомогательные скрипты сверки в репозиторий не входят —
это исходные данные, они закрыты `.gitignore`.
