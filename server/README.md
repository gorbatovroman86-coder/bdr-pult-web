# Хранилище пульта БДР

Маленький сервис: набор параметров, журнал расчётов, курсы валют.
Нужен для того, чтобы цифры были одни и те же с любого компьютера.

> **Адресов, поддоменов, логинов и паролей в этом файле нет и не будет.**
> Они передаются владельцу отдельно и живут только на машине.

---

## Из чего сделан

**Node 24, ноль зависимостей.** `node:http` и встроенный `node:sqlite` —
оба входят в состав Node. Отсюда следует:

- на машине нечего устанавливать и нечего обновлять;
- нет дерева зависимостей, а значит нет и цепочки поставок, через которую
  что-то может приехать;
- один язык на весь проект — пульт тоже на TypeScript.

Python 3.12 на машине есть, но потребовал бы venv, fastapi и uvicorn —
три зависимости там, где хватает нуля.

## Что умеет

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/health` | жив ли сервис |
| GET | `/params` | текущий набор параметров |
| PUT | `/params` | записать набор |
| GET | `/journal` | список записей журнала |
| POST | `/journal` | добавить запись |
| GET | `/journal/<id>` | одна запись целиком |
| DELETE | `/journal/<id>` | удалить запись |
| GET | `/fx` | курсы CNY и USD |

Больше ничего. Каждая операция понадобилась пульту, лишних нет.

### Как устроена защита от затирки

Набор хранится с номером ревизии. `PUT /params` присылает `baseRevision` —
ту ревизию, которую браузер видел последней. Если на сервере уже другая,
запись **не выполняется**, возвращается `409` и текущее серверное состояние.
Пульт показывает оба варианта человеку и ждёт выбора.

Осознанное «оставить моё» проходит с флагом `force`.

### Что не принимается

- набор с полем вне допустимых границ или с пропавшим режимом — `422`
  со списком причин;
- запись журнала с полем `payroll` — **ФОТ в журнал не принимается**;
- тело больше 512 КБ — `413`;
- запрос с любого домена, кроме домена сайта — CORS настроен на один адрес,
  `*` не используется.

### Что попадает в логи

Время, метод, путь, код ответа, длительность. **Значения параметров, цены
и ставки в логи не пишутся никогда** — ни в обычном режиме, ни при ошибке.

## Курсы валют

Два адреса и никаких других:

- `iss.moex.com` — биржа. `CNYRUB_TOM` и `USD000UTSTOM`, доска CETS;
- `www.cbr.ru` — официальный курс, когда биржа молчит.

Источник выбирается **по данным, а не по расписанию**: если биржа отдала
сделку за сегодня — берём её, иначе идём к ЦБ. Календарь праздников
в коде не нужен.

Ответ кэшируется на 10 минут. Не достали — остаётся последнее сохранённое
значение, пульт покажет его возраст.

**К `gov.ru` и МСХ сервис не обращается.** Машина за пределами РФ,
гео-фильтр не пускает; ставки пошлин вводятся вручную.

## Настройки

Задаются переменными окружения в юните.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `BDR_HOST` | адрес docker-моста | **не `0.0.0.0`**: брандмауэра нет, и привязка ко всем интерфейсам открыла бы API в интернет мимо пароля |
| `BDR_PORT` | `18791` | свободный порт |
| `BDR_DB` | `<каталог>/data/bdr.sqlite` | файл базы, вне репозитория |
| `BDR_ORIGIN` | адрес сайта | единственный домен, которому разрешён CORS |

## Установка и обслуживание

Установка, запуск и правка конфига caddy делаются **владельцем вручную** —
пошаговая инструкция передана отдельно. Здесь только напоминание о порядке:

1. скопировать `src/*.mjs` в рабочий каталог на машине;
2. поставить юнит из `deploy/bdr-pult-api.service`;
3. добавить блок из `deploy/caddy-block.txt` в конфиг caddy, подставив
   префикс, пользователя и **хеш** пароля (не пароль);
4. перезапустить сервис, затем caddy;
5. проверить `/health`.

Резервная копия базы — обычное копирование файла `.sqlite` вместе
с `-wal` и `-shm`, либо `sqlite3 <файл> ".backup <куда>"`.

Живут вместе с остальными: `cd app && npm test`. Маршруты проверяются
на базе в памяти, курсы — на подменённом источнике. **Живой сервис
тесты не трогают.**
